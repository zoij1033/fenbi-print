# 粉笔试卷排版打印

把粉笔在线试卷（行测 / 申论）一键排成 A4 真卷：题号悬挂缩进、**屏幕上直接显示 A4 分页**、题目可跨页、申论可选答题格，支持直接打印或导出 PDF。

> 默认**不**加自制封面 / 封底：正式试卷直接沿用粉笔自己的首页封底，只在示意 / 预览页才使用脚本自带的排版页封面封底。
> 生成页会先按 A4 内容区高度把正文切成一张张「纸」，每页底部自动写死页码；屏幕上看到的就是打印出来的样子。切完会实测每页真实高度，真超了就收紧重切，避免文字顶出页面。

**纯本地运行**：不请求任何自己的服务端，没有账号、没有授权、没有次数限制，页面上不植入任何计数逻辑。

> 想分发给别人用？见下方的「分发给别人用」章节，已配好安装引导页 + 小书签 + 油猴 + 可选更新提示。

## 装法

1. 浏览器装 [Tampermonkey](https://www.tampermonkey.net/)（Chrome / Edge / Firefox 均可）。
2. 面板 → **实用工具 → 导入** → 选 `fenbi-print.user.js`；或「添加新脚本」把内容整段粘进去保存。
3. 打开粉笔试卷页（`spa.fenbi.com` 下的行测 / 申论做题页），右上角出现「试卷排版打印」面板。

## 两个按钮

| 按钮 | 作用 |
|---|---|
| **排版并打印** | 抓取当前页全部题目 → 排版 → 新窗口打开 → 等图片就绪后自动唤起打印。选「另存为 PDF」即得电子卷。 |
| **导出PDF** | 与「排版并打印」同源：打开排版页并自动唤起打印对话框，目标选「另存为 PDF」即保存为文件；选真实打印机则直接印到纸。 |

## 排版相关设置（点面板「设置」展开）

| 设置 | 说明 |
|---|---|
| 附自制封面页 | 标准考试封面 + 一页缓冲页；**默认关闭**，只在示意 / 预览演示时勾选 |
| 页边距 | 标准 / 窄边（推荐）/ 极窄 |
| 页脚署名 | 固定显示「工具支持 小红书@火焰百合」，没有开关，也不可改 |
| 字号、行距、题目间距 | 按自己眼睛和用纸量调 |
| 换页方式 | 见下，默认「智能平衡 · 题干按段、选项整行」 |
| 大图缩放 | 只缩实际宽度 > 150px 的图，分数公式之类的小图不动 |
| 申论作答区 | 仅申论生效：默认不留；`按题目字数自动算` 会从题干里读「不超过 200 字」「1000～1200 字」等要求自动给行数；`固定高度` 则按你填的 cm 值统一留 |
| 作答区高度 | `固定高度` 模式时才显示，填厘米数。小题 6～10，大作文 20～26 |
| 对答案二维码 | 末页附二维码；需联网生成，取不到会自动隐藏 |
| 打印倒计时 | 防止另存 PDF 还没写完就关页面导致空白，默认 8 秒，填 0 可直接关 |
| 自动唤起打印 | 关掉则只打开结果页；生成后按 `P` 键可重新唤起打印，`Esc` 关闭倒计时弹窗 |

所有设置自动记忆，面板可拖动，位置也会记下来。

## 分页与跨页

**默认「智能平衡」下题目是可以跨页的** —— 长题目会从当页底部继续到下一页，不会整块被推走留白。

三档策略的差别只在于「允许断到多细」：

| 策略 | 题目容器 | 题干 | 段落内部 | 选项组 |
|---|---|---|---|---|
| **智能平衡**（默认） | 可跨页 | 可跨页，按段落断 | 不断 | 可跨页，短选项组尽量整组同页 |
| 极致省纸 | 可跨页 | 可跨页 | 可断 | 可跨页 |
| 整题不拆 | 不拆 | 不拆 | 不断 | 不拆 |

**三档都保证不会拆开**：单个选项、图片、表格行、各级标题。这几样断开了就没法看了。

想确认效果：打开 `示例-行测试卷.html`，第 6 题是特意放进去的超长题干（5 段材料 + 4 选项），进打印预览就能看到它跨页；第 8 题是带下划线空白的填空题。

## 选项列数

选项排几列是**算出来的**，不写死字数：

1. 先按 A4 内容区宽度（随页边距变化）算出每列能有多宽；
2. 再估每个选项渲染后需要多宽 —— 中文字按 1 个字宽、英文数字按 0.55 个字宽，图片按缩放后的实际宽度；
3. 装不下就逐级降级，直到一行一个。

默认 15px 字号 + 窄边距下大致是：

| 选项长度 | 列数 |
|---|---|
| 7 个汉字以内 | 4 列 |
| 19 个汉字以内 | 2 列 |
| 再长 | 1 列 |

所以**字号调大或页边距调宽时，同样的选项会自动降列**，不会挤成一团。反过来，短选项会尽量并排以省纸。

## 选项字母与内容

选项字母**直接用粉笔自己的**（粉笔把 A/B/C/D 放在 `.input-radio` 节点里），不再先删掉再自己补一个。这样有两个好处：

1. **基线自然对齐**，不再有「A. 比后面的文字低一截」的高度落差。
2. **不会误削正文**：上一版为了去掉「重复前导字母」会遍历清理，结果把像 `AB` 这种本身以 A 开头的选项内容削成 `B`；现在原文一个字都不动，就不会削错。

图形题的选项图片通常自带 A/B/C/D 标注，所以图片选项只显示字母 + 图片，不再额外在图片上方重复渲染字母。

## 页码与首页 / 末页

- **首页不显示页码**（无论首页是自制封面还是粉笔正文首页）。
- **末页也不显示页码**：默认末页是对答案二维码页。
- 其余页面在底部右侧显示真实页码，格式「当前页 / 总页数」（如 `2 / 5`）。

默认关闭自制封面，是因为粉笔导出的试卷本身已有首页和封底，脚本不必再额外画蛇添足。想做一份独立好看的示意页或离线预览，再勾选「附自制封面页」（只会附加封面 + 一页缓冲页，不再额外加封底页）。页脚的「工具支持 小红书@火焰百合」会始终印在正文页底部左侧，首页不印页码但署名照常。

## 填空线

题干里过长的下划线 / 空白会统一替换成一段 `border-bottom` 画出来的填空线。不再用全角下划线字符 `＿` 拼接——不同字体下这些字符会彼此重叠、忽粗忽细，打印出来很难看。

## 选项内容的完整性

排版时只清理选项最开头**明显是重复题号**的部分，不会把选项正文也吃掉：

- 像 `A. AB` 这种，清理后保留 `AB`（不是只剩 `B`）。
- 图形题选项里的图片和自带的 A/B/C/D 标注都会保留，不会再在图片下方额外加一行 `A.` / `B.` / `C.` / `D.` 造成重复。
- 题号、选项字母均使用正常字重，不加粗。

## 打印设置建议

目标选「另存为 PDF」，纸张 A4，边距选「默认」（页边距脚本内已设定），**务必勾选「背景图形」**——否则封面虚线框、表头底色、申论答题格线会丢。

**必须取消勾选「页眉和页脚」**。浏览器默认会打印网页标题/网址（顶部）和日期（底部），脚本无法代你关闭；只有手动取消勾选才能去掉这些额外文字。

## 三个注意点

1. **图片来自粉笔**，导出的 PDF 首次生成需联网，图形题才显示；文字部分离线正常。要彻底离线，先联网打开一次打印成 PDF。
2. 弹窗被拦截时，先允许本站弹出窗口再点按钮（「导出 PDF」也依赖新窗口承载打印页）。
3. 申论要逐个切换材料与题目标签来抓取，比行测慢，耐心等十几秒；面板上会实时显示进度。

## 实现结构

代码分四层，互不纠缠：

```
配置  →  提取（页面 DOM → 结构化数据）  →  渲染（数据 → 打印用 HTML）  →  输出（打印 / 下载）
```

- **提取层**产出统一结构：`{kind:'chapter'}` / `{kind:'material'}` / `{kind:'question'}`，行测与申论两条实现，对下游完全一致。
- **渲染层**只认这份数据，不碰页面 DOM，所以排版样式可以独立调整。
- 生成的 HTML 自包含（样式与脚本内联），可离线打开。

相比在旧脚本上改，重写主要解决的是：**旧版边遍历 DOM 边拼 HTML，提取和排版耦合在一起**，改样式容易碰坏提取逻辑。

### 已避开的坑

这些是实践中踩过的，重写时直接按正确做法写：

- 图片缩放必须**等图片解码完成**再执行（否则测得宽度 0，设置完全失效），且要**幂等**（否则轮询会把图越缩越小）。
- 打印必须**等图片下载完**，否则 PDF 里图形题空白。
- 滚动容器要**自动定位**（`.tis-container` 不一定是真正的滚动区），否则懒加载没触发、卷子缺题且不报错。
- 选项前导字母只清**当前选项最开头明确重复的题号**，选项正文里的 `AB`、`BC` 这类字母组合不会被吃掉。
- 图形题选项里的 A/B/C/D 标注会保留，不再额外渲染一层重复字母。
- 题号节点文本为空时，字母回退为按序 A/B/C/D。
- 打印与导出加并发锁，避免重复提取。

## 分发给别人用

`dist/` 目录是一份完整分发包，上传到你的静态托管即可：

| 文件 | 作用 |
|---|---|
| `install.html` | 安装引导页，含小书签拖拽安装 + 油猴安装引导 |
| `fenbi-print.user.js` | 油猴脚本 |
| `fenbi-print.bookmarklet.js` | 纯 JS 版，供小书签 fetch 并注入 |
| `version.json` | 版本信息，脚本可选读取后提示用户更新 |

三种分发方式：

1. **手动发文件（零成本，推荐先试）**：把 `fenbi-print.user.js` 发给用户，用户在油猴面板「实用工具 → 导入」选文件即可，会自动覆盖旧版。不需要任何服务器。
2. **GitHub + jsDelivr（零成本 + 自动更新）**：脚本推到公开仓库，用 `https://cdn.jsdelivr.net/gh/用户名/仓库@main/fenbi-print.user.js` 分发，jsDelivr 免费且自带 CORS。
3. **自建静态托管（CloudBase 等）**：功能最全，网页能自动提示更新，但可能产生费用。

详细步骤见 [`分发说明.md`](./分发说明.md) —— 里面第 0 节专门对比了这三种，含各自的更新流程。

脚本里的 `REMOTE` 默认留空，此时**完全不联网**，没有任何更新提示；只有你填上托管地址（或用 `build.js 域名` 构建）后才会请求 `version.json`。走手动更新路线的话，这个保持空就行。

## 版本号规则

采用 `主.次.修订`（语义化版本）三段式，**只要动了脚本代码，就必须同步 `fenbi-print.user.js` 里的 `// @version` 与 `const VERSION`、以及 `install.html` 的当前版本标识和本文件更新记录**：

| 位 | 何时升 | 例子 |
|---|---|---|
| 修订号 z | 修 bug、UI 微调等小改动 | 1.6.3 → 1.6.4 |
| 次版本号 y | 新增功能 / 较大改动 | 1.6 → 1.7 |
| 主版本号 x | 破坏性大改（极少动） | — |

> **铁律**：哪怕只补一个函数、调一处样式，版本号也得 +1（通常升修订号）。否则「检查更新」比对到的还是同一个号，永远不会提示有新版本。v1.6.4 就是一次"改了代码却忘了 bump 版本"后的补正。

## 更新记录

### v1.6.7（2026-08-31）

- **修复卷子标题偶尔印错**：真实页面结构样本暴露出一个竞态——面板的「试卷标题」输入框用 `value` 预填占位文字「正在读取当前试卷…」，而 `opt.title` 的取值是 `($('fp-title').value || '').trim() || readPaperTitle()`，占位符非空所以**永远轮不到 `readPaperTitle()` 兜底**。真实试卷名依赖一个 `setTimeout(…, 900)` 回填，这个 900ms 是写死的，而 `.header-title` 由 Angular 异步渲染，耗时不定。三场景实测（无头 Chromium + puppeteer-core 驱动真实 `window.open`）：

  | 场景 | 操作 | 修复前封面印出 |
  |---|---|---|
  | A | 脚本就绪后 100ms 就点生成 | `正在读取当前试卷…` ❌ |
  | B | 等 2.5s 再点 | `2024年福建省公务员录用考试《行测》题（网友回忆版）` ✅ |
  | C | `.header-title` 延迟到 1.5s 才渲染，2.5s 点 | `粉笔题库` ❌ |

  场景 C 最该担心：这份页面的 `<title>` 是静态的「粉笔题库」，真名要等 `.header-title` 渲染出来才有；定时器一旦跑空，`readPaperTitle()` 就退到 `document.title`，封面直接印出「粉笔题库」这种毫无意义的字。
- **改法（两处，缺一不可）**：① 输入框 `value="${TITLE_PLACEHOLDER}"` 改为 `placeholder="${TITLE_PLACEHOLDER}"`——`value` 留空后，生成时就会实时调 `readPaperTitle()`，不再受回填时机影响；② 900ms 定时器改为**轮询**：`pollTitle(deadline)` 每 400ms 查一次 `.header-title, .paper-name, .header-center .title`，查到就回填并停止，最多等 10 秒；用户已改过（`el.value.trim()` 非空）则不再动它。只改 ① 只能救场景 A，场景 C 仍会在 900ms 那个瞬间把「粉笔题库」固化下来——因为定时器是在**写面板的值**，一旦写下，后续生成就拿它当真值了，所以两处必须一起改。
- **附带收益**：用户点进标题框时不再需要先删掉一串占位文字，交互更顺。
- **验证**：修复后 A / B / C 三场景全部输出正确标题；回归确认面板最终回填真实试卷名、`placeholder` 正常显示、用户自定义标题仍优先（生成结果 = `用户自定义的卷子名`）；题干 3 道、选项 10 个、图片 `naturalWidth=120` 加载正常，无 JS 报错。

### v1.6.6（2026-08-31）

- **修复滚动条贴边顶到圆角**：v1.6.5 解决了滚动条"占位导致内容被挤窄 + 宽度跳变"，但滚动条本身仍纵向贯穿整个面板高度——滑到最顶端 / 最底端时，滑块端点距面板上下边缘实测只有 **1px**，正好压在 16px 圆角的弧线上，看上去像把圆角顶破了。
- **改法：把滚动容器从面板本身下沉到内层容器**。`.fp-panel` 改为 `padding:0` + `overflow:hidden` + `display:flex`；新增内层 `.fp-scroll`（`flex:1 1 auto; min-height:0; margin:24px 0; padding:0 15px; overflow-y:auto; scrollbar-gutter:stable both-edges`），滚动条样式（6px / 透明轨道 / Firefox 的 `scrollbar-width:thin`）一并从 `.fp-panel` 迁到 `.fp-scroll`。因为滚动条绘制在内层容器的 padding box 上，而该容器距面板上下各 24px 外边距，滑块端点自然被推到距面板边缘 **25px**（像素实测 25.5px = 24px margin + 1px border）处，彻底避开 16px 圆角。
- **为什么不用更省事的 `::-webkit-scrollbar-track{margin:24px 0}`**：实测它同样能留白（数值完全一样），但 `::-webkit-scrollbar` 系列**火狐完全不认**，作者主力浏览器就是火狐，故弃用，改走内层容器方案——Chrome / Edge / Safari / 火狐 四者表现一致。
- **留白 25px 的数学约束（改数值前必读）**：滚动条绘制区域 = 内层容器的 **padding box**，内容区 = **content box**，二者相差一个 `padding-top`。所以「滚动条留白」= `margin + 1px 边框`，「内容上留白」= `margin + padding-top`，**前者不可能小于后者**（padding 不能为负，硬凑只能靠子元素负 margin，会导致滚动时被裁）。因此把留白从 13.5px 提到 25px，内容上下留白会同步从 15px 涨到 25px；好在左右留白是 22px（1 边框 + 6 gutter + 15 padding），与 25px 只差 3px，视觉上基本均匀。若将来要四周严格一致，需要把面板加宽到 320px（content 仍为 258px）。
- **滚动条改成偏灰的淡蓝 `#c3d2e8`**：原色 `#cbd5e1`（Tailwind slate-300）饱和度只有约 13%，在白底上几乎看不出是蓝的、只当是一根灰条。`#c3d2e8`（HSL 217° / 44% / 84%）蓝味出来了但依旧很淡，不抢内容。`scrollbar-color` 与 `::-webkit-scrollbar-thumb` 两处同步替换，火狐同样生效；像素采样已验证渲染结果就是 `RGB(195,210,232)`。其余候选：`#b9c9de`（更偏灰）、`#b0c4de`（亮钢蓝，蓝味更重）、`#a3b8d4`（更显眼）。
- **打印完成弹窗的禁用态按钮改深 `#cbd5e1` → `#94a3b8`**：该按钮是「生成中/未就绪」的禁用态（`disabled`），就绪后加 `.on` 变成蓝 `#2563eb`。原来的 `#cbd5e1` 配白字，对比度只有 **1.48:1**，基本等于白字浮在白底上，字根本看不清。按作者选定改为 slate-400 `#94a3b8`，白字对比度 **2.56:1**（比原色提升 73%，视觉上明显能读，但未达 WCAG AA 的 4.5:1——这是作者权衡「不想压过蓝色激活按钮」后的主动取舍）。若日后要既保住这个底色又合规，把白字换成深色 `#1e293b` 即可到 **5.71:1**（激活态蓝 `#2563eb` 白字为 5.17:1）。
- **顺带修掉完成弹窗里的两个真 bug**：
  1. **按钮容器样式选择器写错**：CSS 写的是 `#fp-done-btns`（id 选择器），而 HTML 用的是 `class="fp-done-btns"`——这条 `display:flex;gap:12px;justify-content:center` 规则**从未生效过**，两个按钮一直紧挨着。实测像素：改前两按钮间距 **0.5px**，改后 **12.5px**。已改为 `.fp-done-btns`。
  2. **`cursor:not-allowed` 作用域过大**：原先挂在 `#fp-done button` 上，导致倒计时结束后「留在页面」已 `removeAttribute('disabled')`、明明可点，鼠标移上去却仍显示禁止光标。现已收窄为 `#fp-done button[disabled]`，基础规则改为 `cursor:pointer`。
- **关键数值保持不变**：内容宽度仍为 258px，左右间隙 22 / 22 对称居中，面板宽度 302px，展开与收起之间零跳变（无头 Chromium 实测：展开态 `panelW=302 / inputW=258 / gapL=22 / gapR=22 / contentTopGap=25 / canScroll=true`；像素级测量滑块距面板顶/底均为 25.5px，改前为 1px）。

#### 打印完成弹窗：倒计时改为「一弹出就开始」

- **原行为（不符合预期）**：`startCountdown()` 这个函数名有误导性——它只负责**显示**弹窗，倒计时根本不在里面。真正的倒计时写在「关闭页面」按钮的点击回调里，且是"首次点击才启动、再点一次才立即关闭"。也就是说，**不点按钮就永远不会自动关闭**，设置里的「关闭页面倒计时」只在点了按钮之后才起作用。
- **新行为**：`afterprint`（打印对话框关闭）一触发就弹窗 + **立即起倒计时**，按钮上实时显示 `关闭页面 (Ns)`；期间点「关闭页面」立即关闭，点「留在页面」取消，`CD` 填 0 则完全不自动关闭（只留手动按钮）。`focus` 事件保留为兜底（个别浏览器不触发 `afterprint`），但只在弹窗从未出现过时才补一次，避免切窗口回来反复弹窗。
- **顺带修掉一个隐藏很深的坑**：原先按 `Esc` 或点「留在页面」只做 `display:none`，**没有停掉倒计时**——用户以为已经取消，结果 10 秒后页面被 `window.close()` 悄悄关掉。现统一走 `hideDone()`：先 `stopCloseTimer()` 再隐藏，并把按钮文案复位。
- **按钮宽度不再跳动**：倒计时文案从「关闭页面」变成「关闭页面 (10s)」宽度会变（实测 104px → 140.6px），两个按钮互相挤压。给 `#fp-done button` 加 `min-width:141px`（141×2 + 12 gap = 294px，正好塞进弹窗内容区 300px），两态宽度一致。
- **运行时验证**（无头 Chromium，模拟 `afterprint`）：初始隐藏且按钮禁用 → 打印后 `display:flex` 且按钮启用、文案 `关闭页面 (10s)` → +3.1s 变 `7s` → 点「留在页面」隐藏并复位 → +2.5s 未自动关闭 → 再次打印重新起 10s → 点「关闭页面」`close()` 被调用 → `Esc` 后 +2.5s 未自动关闭。`CD=0` 单独验证：弹窗正常显示、3.2s 后仍未自动关闭、点按钮立即关闭。

#### 分页收集：修掉两处「内容凭空消失」

自检时用模拟粉笔页面跑端到端，抓出两个会**丢内容**的真 bug，都出在 `collect()` 把 `#fp-flow` 拆成可搬移原子的环节：

1. **材料整段丢失**：`collectMat()` 只认 `P` / `TABLE` / `IMG` 三种叶子，遇到"正文直接包在 `div.content` / `.material-content` 里、没有元素子节点"的叶子容器时，`for` 循环一次都不执行，**一个原子都不产生** → 材料在分页环节被整个丢掉（面板上还显示"1 份材料"，PDF 里却空空如也）。已加兜底：无元素子节点的容器整块收下。
2. **混排文本丢失（影响更大）**：`drill()` 与 `collectMat()` 递归时只遍历 `node.children`（元素子节点），**挂在容器上的裸文本节点一个都不收**。粉笔的题干/材料大量是 `<div>……最恰当的一项是：<span>____</span>。</div>` 这种混排结构，结果就是**题干只剩中间那个 span，前后文字全没了**。已改为：容器上只要有非空直接文本，就整块收下——拆成"文本块 + 元素块"也不行，那会打断行内流、把一句话劈成两行；整块收下最保真，代价只是这一块不能跨页续排。
- **代价与取舍**：混排块不可拆，页尾留白会比"能逐段拆"时略多。换来的是内容零丢失——在"省纸"和"不丢字"之间，后者没有商量余地。
- **端到端验证**：模拟 4 种材料结构（div 纯文本 / 标准 p 段落 / 整块表格 / div 混排 p）+ 混排题干 + 图片选项题，修复前「丁材料」与「混排题干前后半段」均为 `false`，修复后全部 `true`；申论模式（模拟 tab 切换）2 份材料 + 3 道题 + 作答区全部正常，分页无溢出。

- **彻底修复打印时每页后面多一张空白页**：根因不是 v1.5.1 以为的「亚像素撑高」，而是**页边距不匹配**——脚本假定 `@page` 边距 15mm 并按 `(297−30)mm` 算每页高度，但 Chrome 打印对话框「默认」边距约 20mm（大于 15mm），可打印高度被压到比每页高度还小，于是每个 `.fp-page` 都溢出几像素，`page-break-after:always` 被迫把溢出部分再分一页空白。现改为 **`@page{margin:0}` + 每页钉死成整张 A4（297mm）、可视边距改由页面内部 `padding` 提供**：无论对话框选「默认 / 最小 / 无」边距，每页都正好占满一张纸，分页唯一且确定，不再多挤空白页。无头浏览器实测：10 页正文 → 正好 10 页 PDF，零空白页。

### v1.5.1（2026-08-30）

- **修复打印时每页后面多一个空白页**：`@media print` 下 `.fp-page` 原先是 `height:auto;min-height:${CONTENT_H}px`，浏览器实际排版时内容+页脚容易因字体/边距亚像素差异微微撑高，导致每个 `.fp-page` 占满一页还多出一点，`page-break-after:always` 于是强制在溢出部分再分一页空白。现改为固定高度 `height:${CONTENT_H}px;max-height:${CONTENT_H}px;overflow:hidden`，同时 `.fp-pbody` 也限制 `max-height:${BODY_H}px;overflow:hidden`，确保每页严格落在 A4 内容区内。
